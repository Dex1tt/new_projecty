# Project instructions

- Communicate with the user in Russian.
- Inspect the existing code and Git status before editing. Preserve unrelated changes.
- Use focused changes and meaningful commits. Use feat/* or fix/* branches for substantial work.
- Before committing, inspect the staged diff and run checks appropriate to the change.
- Do not commit secrets, dependency directories or generated build output.
- Do not force-push or rewrite shared history unless explicitly requested.
- Add linting, type checks and CI once the application stack and scripts exist.
- Validate UI changes in a browser when practical.
